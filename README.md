# Фіди Гарбуза для маркетплейсів

## epicentr_stock.xml

Файл автооновлення цін і наявності для Епіцентр Маркетплейс.

**Пряме посилання для кабінету Епіцентра:**

```
https://raw.githubusercontent.com/enagrosvit-beep/epicentr/main/epicentr_stock.xml
```

### Як підключено

Кабінет продавця Епіцентр → Товари → Імпорт → вкладка **«Автооновлення залишків»**:

1. поле «Посилання на файл» — посилання вище;
2. увімкнено чекбокс **«Змінити статус товарів, яких немає у файлі, на "Немає в наявності"»**;
3. Епіцентр забирає файл **раз на добу, з 00:00 до 02:00** за Києвом.

### Що всередині

Мінімальний YML: артикул, ціна, наявність. Без характеристик — цей файл
**не створює нові картки**, лише оновлює ціну й наявність у наявних.

```xml
<offer id="PLX-134" available="true">
<price>59</price>
</offer>
```

Джерело — каталог harbuz.in.ua, знято через API магазину (`/api/catalog/export/`).

### Оновлення — автоматичне

`.github/workflows/update-feed.yml` запускає `build_feed.py` **щодня о 21:00 UTC
(00:00 за Києвом)** — за кілька хвилин до вікна, в яке Епіцентр забирає файл.
Якщо ціни й наявність не змінились, коміту не буде.

Ручний запуск: вкладка **Actions → «Оновити фід Епіцентра» → Run workflow**.

#### Потрібні секрети репозиторію

Settings → Secrets and variables → Actions → New repository secret:

| Ім'я | Значення |
|---|---|
| `HS_LOGIN` | логін API магазину Гарбуз |
| `HS_PASS` | пароль до нього |

Без цих двох секретів workflow впаде на кроці генерації.

#### Захисники в `build_feed.py`

* свіжий токен перед **кожною** сторінкою експорту (TTL токена — 600 с);
* ліміт 429 у Horoshop приходить як HTTP 200 з тілом «Retry after N» — ловиться
  текстом і перечікується;
* якщо каталог раптом скоротився більш ніж на **5%**, файл **не перезаписується**
  і workflow падає з помилкою: це майже завжди ознака неповного витягу, а не
  того, що товари зникли.
